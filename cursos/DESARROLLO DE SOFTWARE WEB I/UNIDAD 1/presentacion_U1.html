La "Edad Oscura" del Código

Antes de los frameworks, los desarrolladores sufrían de "Código Espagueti".

  • Mezcla de lenguajes: PHP, HTML, CSS y SQL en un mismo archivo.
  • Mantenimiento imposible: Cambiar el diseño requería modificar consultas a bases de datos.
  • Reinvención constante: Cada desarrollador escribía su propio sistema de login desde cero.
index.php (El Horror)
<?php $conn = mysqli_connect("localhost", "root", "", "db"); $res = mysqli_query($conn, "SELECT * FROM users"); ?> <html><body> <?php while($row = mysqli_fetch_assoc($res)) { ?> <div class="user"><?php echo $row['name']; ?></div> <?php } ?> </body></html>

Entonces, ¿Qué es un Framework?

Una plataforma de desarrollo preestablecida. Un marco de trabajo que proporciona herramientas listas para usar.

La regla de Inversión de Control

En una librería, tú llamas al código. En un framework, el framework llama a tu código.

Provee la plomería (enrutamiento, seguridad, conexión a DB) para que tú te enfoques en la decoración (lógica de negocio e interfaz).

Frameworks: Pros y Contras

Ventajas Principales

  • Velocidad: Tareas comunes (login, base de datos) ya están resueltas.
  • Seguridad: Prevención contra inyecciones SQL y XSS.
  • Trabajo en Equipo: Estructura estandarizada conocida por todos.

Desventajas a considerar

Curva de aprendizaje pronunciada al inicio. Para proyectos muy simples (ej. una landing page de 1 página), usar un framework puede ser "matar una mosca con un cañón" (Overhead de rendimiento).

El Patrón MVC

El estándar de la industria. Divide la aplicación en tres capas de responsabilidad.

Model

Los datos.

View

La interfaz (HTML).

Controller

El puente/lógica.

Capa 1: El Modelo (Model)

El cerebro de los datos. Representa las entidades de tu negocio.

  • Se encarga de acceder a la Base de Datos.
  • Contiene las reglas de negocio (Ej: Un usuario no puede ser menor de 18 años).
  • En Laravel, los Modelos se comunican usando un sistema llamado Eloquent ORM.
Ejemplo: User.php
class User extends Model { // Ocultar contraseñas al pedir datos protected $hidden = ['password']; // Regla: Un usuario tiene muchos posts public function posts() { return $this->hasMany(Post::class); } }

Capa 2: La Vista (View)

La cara de la app. Es lo que el usuario final ve e interactúa.

Ejemplo: perfil.blade.php
<h1>Perfil de {{ $user->name }}</h1> <div class="card"> <p>Email: {{ $user->email }}</p> </div>
  • Aquí vive el HTML, CSS y JavaScript.
  • Las Vistas son pasivas: no piden datos a la base de datos, solo muestran lo que el Controlador les entrega.
  • En Laravel se construyen usando el motor Blade.

Capa 3: El Controlador

El director de orquesta. Conecta el Modelo con la Vista.

  • Recibe la petición HTTP del usuario.
  • Pide los datos necesarios al Modelo.
  • Le inyecta esos datos a la Vista y la retorna al navegador.
Ejemplo: UserController.php
public function show($id) { // 1. Pide datos al Modelo $usuario = User::find($id); // 2. Retorna la Vista con los datos return view('perfil', [ 'user' => $usuario ]); }

Estructura de Directorios

Al crear un proyecto nuevo, verás decenas de carpetas. No te asustes, la convención sobre configuración es tu aliada.

app/
Backend (Modelos, Controladores).
bootstrap/
Archivos del framework.
config/
Configuración.
database/
Tablas de BD (Migraciones).
public/
Acceso web (index.php, CSS).
resources/
Vistas (Frontend).
routes/
URLs.
.env
Contraseñas secretas.

Focus: app/ y public/

app/

El corazón de tu aplicación. Aquí vives la mayor parte del tiempo programando la lógica.

  • app/Http/Controllers/ (Controladores)
  • app/Models/ (Modelos)

public/

El ÚNICO directorio expuesto a internet. Tu servidor Apache/Nginx debe apuntar aquí.

  • Contiene el index.php que arranca todo.
  • Aquí colocas tus imágenes, logos, CSS y JS compilado.

Focus: resources/ y routes/

resources/

El directorio del Frontend.

  • resources/views/: Aquí van todos tus archivos .blade.php.
  • resources/css/: CSS sin procesar (Tailwind/Sass).

routes/

El mapa de navegación de tu app.

  • routes/web.php: Rutas para usuarios (Navegador).
  • routes/api.php: Rutas para APIs (Móviles, React).

Conoce a Artisan

Artisan es el asistente de Interfaz de Línea de Comandos (CLI) incluido con Laravel.

Terminal
# Para ver todo lo que Artisan puede hacer por ti, ejecuta: php artisan list
Ejecuta código PHP desde la consola, genera archivos base, limpia cachés y ejecuta migraciones.

Artisan: Servidor y Mantenimiento

Levantar el Servidor

php artisan serve

Inicia el servidor local de desarrollo de PHP. No necesitas instalar XAMPP ni WAMP para que Laravel funcione localmente.

Limpiar Caché

php artisan optimize:clear

¿Cambiaste código y no se ve en el navegador? Laravel cachea rutas y vistas para ser más rápido. Este comando borra esa memoria.

Artisan: Generadores (Make)

No crees archivos a mano. Deja que Artisan cree la estructura base por ti.

  • php artisan make:controller NameController Genera un controlador vacío.
  • php artisan make:model Nombre Genera un modelo en app/Models.
  • php artisan make:model Nombre -m El flag -m también crea automáticamente el archivo de migración (tabla BD).
Recordatorio: NO existe php artisan make:view por defecto. Las vistas se crean manualmente como nombre.blade.php.

Enrutamiento: El Recepcionista

El archivo routes/web.php intercepta cada petición al servidor web.

  • web.php: Aquí van las rutas con interfaz web (aplican cookies, sesiones, seguridad CSRF).
  • api.php: Aquí van rutas para APIS puras de datos (sin estado, tokens).
routes/web.php
use App\Http\Controllers\ProjectController; // Ruta simple Route::get('/', function () { return view('welcome'); }); // Ruta conectada a Controller Route::get('/proyectos', [ProjectController::class, 'index']);

Routing: Verbos HTTP

Las rutas no solo responden a la URL, sino al "Verbo" HTTP utilizado.

GET

Para SOLICITAR datos. (Ej: Cargar la página web, ver un formulario).

Route::get(...)

POST

Para ENVIAR datos nuevos. (Ej: Guardar el formulario relleno en la BD).

Route::post(...)

PUT / PATCH

Para ACTUALIZAR datos existentes.

Route::put(...)

DELETE

Para ELIMINAR datos.

Route::delete(...)

Routing: Parámetros Dinámicos

Extrae valores directamente desde la URL de forma elegante.

routes/web.php
// El parámetro va entre llaves {id} Route::get('/usuarios/{id}', function ($id) { return 'Mostrando información del usuario ID: ' . $id; }); // También se inyecta directamente al Controlador Route::get('/proyectos/{id}', [ProjectController::class, 'show']);
Al visitar tusitio.com/proyectos/42, el controlador recibirá la variable $id = 42 automáticamente.

El Controlador al descubierto

Organiza tu lógica agrupando peticiones relacionadas en una sola clase.

app/Http/Controllers/ProjectController.php
namespace App\Http\Controllers; use Illuminate\Http\Request; use App\Models\Project; // Importar el modelo class ProjectController extends Controller { public function show($id) { $proyecto = Project::find($id); // Se pasa el dato a la vista usando un arreglo asociativo return view('proyectos.detalle', ['project' => $proyecto]); } }

Controladores: El Truco --resource

Comando: php artisan make:controller NameController --resource

Te genera una clase con los 7 métodos estándar (RESTful) para un CRUD completo:

  • index() - Muestra una lista (GET)
  • create() - Muestra form de crear (GET)
  • store() - Guarda en BD (POST)
  • show($id) - Muestra 1 elemento (GET)
  • edit($id) - Muestra form editar (GET)
  • update($id) - Actualiza BD (PUT)
  • destroy($id) - Borra en BD (DELETE)

Diseñando con Blade

Blade usa llaves dobles {{ }} para inyectar variables en el HTML. Todo archivo de vista debe terminar en .blade.php.

Impresión Segura (Escapada)

{{ $nombre }}

Protege contra XSS (Cross-Site Scripting). Si $nombre contiene un script malicioso <script>, Blade lo convierte en texto plano inofensivo automáticamente.

Lógica de Negocio prohibida

Blade es solo para mostrar. No hagas conexiones a base de datos ni calculos complejos dentro de tus vistas.

Blade no restringe tu HTML. Puedes seguir usando Bootstrap, Tailwind o CSS puro libremente.

Blade: Impresión Cruda (Raw)

¿Qué pasa si la variable SÍ debe renderizar HTML intencionalmente?

Si recibes texto de un editor de texto enriquecido (Rich Text Editor) y usas {{ }}, se mostrarán las etiquetas <strong> como texto plano.

Usa la inyección cruda: {!! $html !!}

PELIGRO

Úsalo solo si tú controlas al 100% el origen del texto. Si muestras comentarios de usuarios con {!! !!}, estás abriendo la puerta a que hackeen a tus visitantes (XSS).

Directivas Condicionales @if

Adiós a las feas etiquetas <?php if(): ?>

  • @if / @elseif / @else: Condicionales clásicos. No olvides cerrar con @endif.
  • @unless: Lo opuesto a IF. "Ejecuta A MENOS QUE la condición sea verdadera".
  • @empty: Verifica si un array está vacío. Excelente para bases de datos vacías.
@if(count($registros) === 1) <p>Un registro.</p> @else <p>Múltiples registros.</p> @endif @empty($proyectos) <div class="alert">No hay proyectos aún.</div> @endempty

Iteraciones y la variable $loop

Iterar sobre datos provenientes de la base de datos es muy común.

El Superpoder $loop

Dentro de un @foreach, Blade inyecta una variable especial para controlar el estado del bucle:

  • $loop->first : ¿Es el 1ro?
  • $loop->last : ¿Es el último?
  • $loop->iteration : El índice (1,2,3...).
<ul> @foreach($usuarios as $user) <li> @if($loop->first) <strong>Líder:</strong> @endif {{ $user->name }} </li> @endforeach </ul>

Reutilización 1: Layouts (Herencia)

DRY (Don't Repeat Yourself). Nunca repitas el head, el navbar o el footer de tu HTML.

1. El Molde (layouts/app.blade.php)
<html> <body> <nav>Mi Navbar Global</nav> <main> <!-- Marcador de posición --> @yield('contenido') </main> </body> </html>
2. La Página (inicio.blade.php)
<!-- Heredar el molde --> @extends('layouts.app') <!-- Rellenar el marcador --> @section('contenido') <h1>Bienvenido al Inicio</h1> <p>Este texto va dentro de main.</p> @endsection

Reutilización 2: Includes y Componentes

Para fragmentos de UI reutilizables como tarjetas, botones o alertas.

@include

Pega un bloque de código estático. Excelente para inyectar un footer o un sidebar que es idéntico en todos lados.

@include('partials.footer')

Components

Creas etiquetas HTML personalizadas. Puedes pasarle parámetros. Es la forma moderna recomendada.

<x-alert type="danger">Error</x-alert>

FAQ: El problema del Git Clone

¿Bajaste un proyecto de GitHub y sale Error 500? Las librerías (vendor) y credenciales (.env) NUNCA se suben a Git por seguridad.

Terminal: La Receta Mágica (Ejecutar en orden)
# 1. Instalar las dependencias que faltan composer install # 2. Clonar el archivo de ejemplo para crear tu .env real cp .env.example .env # 3. Generar la llave de seguridad de tu app (se guarda en .env) php artisan key:generate # 4. Iniciar el servidor local php artisan serve
