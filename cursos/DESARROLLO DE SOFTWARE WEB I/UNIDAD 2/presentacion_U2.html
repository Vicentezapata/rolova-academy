¿Qué son las Migraciones?

Las migraciones son el control de versiones de tu base de datos. Igual que Git, pero para tablas y columnas.

  • Cada migración es un archivo PHP con los cambios a la BD.
  • Todo el equipo puede replicar la BD exacta con un comando.
  • Se puede deshacer (rollback) si algo sale mal.
  • Laravel registra qué migraciones ya fueron ejecutadas en la tabla migrations.

Anología perfecta

Sin migraciones: «Oye, crea una columna telefono en la tabla users. Es varchar(20). Házlo a mano en MySQL.»

Con migraciones: git pull + php artisan migrate y todos tienen la misma BD.

Creando una Migración

Artisan genera el archivo base. Tú defines qué columnas tendrá la tabla.

Terminal
# Modelo + Migracion juntos (recomendado) php artisan make:model Proyecto -m # Ejecutar migraciones pendientes php artisan migrate # Deshacer la ultima migracion php artisan migrate:rollback # Borrar TODO y volver a migrar php artisan migrate:fresh # Migrar Y sembrar datos php artisan migrate:fresh --seed

Anatomía de una Migración

El archivo tiene dos métodos: up() para crear y down() para deshacer.

database/migrations/2024_01_01_create_proyectos_table.php
return new class extends Migration { public function up(): void { Schema::create('proyectos', function (Blueprint $table) { $table->id(); // PK autoincremental $table->string('nombre', 150); // VARCHAR(150) $table->text('descripcion')->nullable(); // TEXT opcional $table->decimal('monto', 10, 2); // DECIMAL para dinero $table->enum('estado', ['activo','inactivo'])->default('activo'); $table->date('fecha_inicio'); $table->timestamps(); // created_at, updated_at }); } public function down(): void { Schema::dropIfExists('proyectos'); } };

Relaciones: Claves Foráneas

Para relacionar tablas entre sí, usamos Foreign Keys. Laravel las maneja de forma elegante.

Forma moderna (Laravel 7+)
// Migracion de 'tareas' $table->id(); $table->string('titulo'); // FK hacia tabla 'proyectos' $table ->foreignId('proyecto_id') ->constrained() // infiere tabla 'proyectos' ->onDelete('cascade'); // borra tareas si borra proyecto $table->timestamps();

onDelete opciones

  • cascade — Elimina filas hijas automáticamente.
  • restrict — Error si hay hijos.
  • set null — Pone NULL en la FK.
⚠️ Migrar primero la tabla padre (proyectos) antes que la hija (tareas).

Eloquent ORM: El Modelo

Eloquent es el puente entre PHP y la base de datos. Un modelo = una tabla. Sin SQL.

app/Models/Proyecto.php
namespace App\Models; use Illuminate\Database\Eloquent\Model; use Illuminate\Database\Eloquent\Factories\HasFactory; class Proyecto extends Model { use HasFactory; // Para usar Factories // Columnas permitidas asignacion masiva protected $fillable = [ 'nombre', 'descripcion', 'monto', 'estado', 'fecha_inicio' ]; // Relacion: Proyecto tiene muchas Tareas public function tareas() { return $this->hasMany(Tarea::class); } }
  • Laravel infiere la tabla: Proyecto → proyectos.
  • $fillable protege contra ataques de Mass Assignment.
  • Relaciones como métodos PHP.
  • HasFactory habilita las Factories de prueba.

Eloquent: CRUD sin SQL

Las 4 operaciones fundamentales en PHP elegante.

CREATE — Crear
Proyecto::create([ 'nombre' => 'Tech Solutions', 'monto' => 15000, 'estado' => 'activo', 'fecha_inicio' => '2024-03-01', ]);
READ — Leer
Proyecto::all(); Proyecto::find(1); Proyecto::where('estado','activo') ->orderBy('nombre') ->get();
UPDATE — Actualizar
$p = Proyecto::find(1); $p->update(['estado'=>'inactivo']); // O directamente: $p->estado = 'inactivo'; $p->save();
DELETE — Eliminar
$p = Proyecto::find(1); $p->delete(); // Una sola linea: Proyecto::destroy(1);

Seguridad: $fillable vs $guarded

La asignación masiva es poderosa pero peligrosa. Debes proteger tu modelo.

$fillable (LISTA BLANCA)

Solo las columnas listadas pueden asignarse masivamente. Todo lo demás se ignora. Más seguro.

protected $fillable = [ 'nombre', 'monto', 'estado' ];

$guarded (LISTA NEGRA)

Las columnas listadas NO pueden asignarse masivamente. El resto sí puede.

protected $guarded = ['id']; // Todo lo demas es asignable
⚠️ Nunca uses protected $guarded = [] (vacío). Abre la puerta a Mass Assignment.

El Controlador con Base de Datos real

Así queda un Resource Controller completo usando Eloquent.

app/Http/Controllers/ProyectoController.php
use App\Models\Proyecto; use Illuminate\Http\Request; class ProyectoController extends Controller { public function index() { $proyectos = Proyecto::orderBy('nombre')->get(); return view('proyectos.index', compact('proyectos')); } public function store(Request $request) { $request->validate([ 'nombre' => 'required|max:150', 'monto' => 'required|numeric|min:0', ]); Proyecto::create($request->validated()); return redirect()->route('proyectos.index') ->with('success', 'Proyecto creado.'); } public function destroy(Proyecto $proyecto) { $proyecto->delete(); // Route Model Binding automatico return back()->with('success', 'Eliminado correctamente.'); } }

Validación en el Controlador

Laravel valida los datos del usuario antes de tocar la base de datos.

Reglas de validación más comunes
$request->validate([ 'nombre' => 'required|string|max:150', 'email' => 'required|email|unique:users', 'monto' => 'required|numeric|min:0', 'fecha' => 'required|date|after:today', 'estado' => 'required|in:activo,inactivo', 'foto' => 'nullable|image|max:2048', ]);
  • Si falla, Laravel redirige con los errores disponibles en Blade.
  • En Blade: @error('nombre') {{ $message }} @enderror
  • Datos anteriores con old('campo').
FormRequest: Para validaciones complejas usa php artisan make:request StoreProyectoRequest.

Route Model Binding

Laravel inyecta el modelo directamente desde la URL. Cero código extra.

Sin Route Model Binding (manual)
public function show($id) { $proyecto = Proyecto::findOrFail($id); return view('proyectos.show', compact('proyecto')); }
Con Route Model Binding (automatico)
// Laravel hace findOrFail($id) solo // 404 automatico si no existe public function show(Proyecto $proyecto) { return view('proyectos.show', compact('proyecto')); }

¿Cómo funciona?

La ruta es /proyectos/{proyecto}.

El parámetro {proyecto} coincide con el argumento Proyecto $proyecto.

Laravel ejecuta Proyecto::findOrFail($id) automáticamente.

Aplica igual en edit, update y destroy.

¿Qué son los Seeders?

Los Seeders «siembran» datos iniciales en la base de datos de forma programática.

Datos de Desarrollo

Llenar la BD con datos realistas para trabajar sin ingresar todo a mano.

Datos Esenciales

Datos que siempre deben existir: roles, categorías, usuarios admin.

Reproducibilidad

Cualquier miembro del equipo obtiene la misma BD con el mismo comando.

Terminal
# Crear un seeder php artisan make:seeder ProyectoSeeder # Ejecutar TODOS los seeders php artisan db:seed # Ejecutar SOLO uno especifico php artisan db:seed --class=ProyectoSeeder # Migrar Y sembrar en un solo comando php artisan migrate:fresh --seed

Anatomía de un Seeder

Todo el trabajo ocurre dentro del método run().

database/seeders/ProyectoSeeder.php
class ProyectoSeeder extends Seeder { public function run(): void { // Registro concreto real Proyecto::create([ 'nombre' => 'Tech Solutions', 'descripcion' => 'Sistema de gestion', 'monto' => 15000.00, 'estado' => 'activo', 'fecha_inicio' => '2024-01-15', ]); // 10 registros aleatorios con Factory Proyecto::factory()->count(10)->create(); } }
database/seeders/DatabaseSeeder.php
class DatabaseSeeder extends Seeder { public function run(): void { // Orchestrador: llama tus seeders // Orden importa si hay FKs $this->call([ ProyectoSeeder::class, TareaSeeder::class, UserSeeder::class, ]); } }
Registra todos los seeders en DatabaseSeeder para ejecutarlos con db:seed.

¿Qué son las Factories?

Las Factories generan datos falsos pero realistas automáticamente usando la librería Faker.

  • Generan nombres, emails, empresas, números... todo aleatorio y coherente.
  • Genera 100 proyectos de prueba con una sola línea.
  • Indispensables para testing automatizado.
  • Faker soporta múltiples idiomas (es_ES, es_CL, etc.).
Terminal
# Crear factory para Proyecto php artisan make:factory ProyectoFactory # Junto con el modelo: php artisan make:model Proyecto -mf # -m = migracion, -f = factory # Todo en uno: php artisan make:model Proyecto -mcf # -c = controller

Anatomía de una Factory

Define el esquema de datos falsos en el método definition().

database/factories/ProyectoFactory.php
class ProyectoFactory extends Factory { public function definition(): array { return [ 'nombre' => fake()->company(), 'descripcion' => fake()->paragraph(), 'monto' => fake()->randomFloat(2, 1000, 50000), 'estado' => fake()->randomElement([ 'activo','inactivo']), 'fecha_inicio' => fake()->dateTimeBetween( '-1 year','now'), ]; } }

Métodos útiles de Faker

fake()->name()Nombre completo
fake()->email()Email único
fake()->company()Empresa
fake()->text(200)Texto largo
fake()->numberBetween(1,100)Número rango
fake()->imageUrl()URL de imagen

Factories + Seeders: La dupla perfecta

Combina factories con seeders para máxima productividad.

database/seeders/ProyectoSeeder.php — run()
// 1 proyecto concreto real Proyecto::create(['nombre' => 'Mi Empresa S.A.', 'monto' => 99999]); // 50 proyectos aleatorios para desarrollo Proyecto::factory()->count(50)->create(); // States: forzar un campo especifico Proyecto::factory()->count(5)->create([ 'estado' => 'inactivo' ]); // Proyectos con Tareas anidadas (relaciones) Proyecto::factory() ->count(10) ->has(Tarea::factory()->count(3)) ->create(); // 10 proyectos, 3 tareas c/u
Comando final: php artisan migrate:fresh --seed → BD limpia + datos frescos en segundos.

Formularios Blade con @method y @csrf

Los formularios HTML solo soportan GET y POST. Para PUT y DELETE, Blade tiene la solución.

resources/views/proyectos/edit.blade.php
<form action="{{ route('proyectos.update', $proyecto) }}" method="POST"> <!-- Token CSRF: SIEMPRE obligatorio --> @csrf <!-- Simula el metodo PUT --> @method('PUT') <input type="text" name="nombre" value="{{ old('nombre', $proyecto->nombre) }}"> @error('nombre') <span>{{ $message }}</span> @enderror <button type="submit">Actualizar</button> </form>
  • @csrf genera un token secreto que previene ataques CSRF. Obligatorio en todos los POST.
  • @method('PUT') agrega campo oculto _method=PUT que Laravel intercepta.
  • old('campo') repopula el valor si hubo error de validación.

El Problema N+1

El error de rendimiento más común con ORMs. Cada relación en un loop = 1 query extra.

MAL — N+1 Queries
// 1 query para todos los proyectos $proyectos = Proyecto::all(); // En Blade: 1 query POR proyecto @foreach($proyectos as $p) {{ $p->cliente->nombre }} @endforeach // = 1 + N queries
BIEN — Eager Loading
// with() carga la relacion de una vez $proyectos = Proyecto:: with('cliente')->get(); // Sin queries extras en Blade @foreach($proyectos as $p) {{ $p->cliente->nombre }} @endforeach // = Solo 2 queries totales

Regla de oro

Si iterarás una relación dentro de un @foreach en Blade, siempre cárgala con with() en el controlador.

Con 100 proyectos sin Eager Loading = 101 queries. Con Eager Loading = 2 queries.

Errores frecuentes y soluciones

SQLSTATE[42S02]: Table not found

Olvidaste ejecutar php artisan migrate.

Add [campo] to fillable property

El campo no está en $fillable del modelo.

419 Page Expired (CSRF)

Olvidaste @csrf en el formulario POST.

Class not found en Seeder

Ejecuta composer dump-autoload.

Trying to get property of null

Usa findOrFail() en lugar de find().

Target class does not exist (Factory)

El modelo no tiene use HasFactory.

Buenas Prácticas

Diferencia entre código que funciona y código que es profesional.

Validar antes de guardar

Nunca confíes en los datos del usuario. $request->validate() es tu primer escudo.

$fillable en todos los modelos

Define explícitamente qué columnas son asignables. Nunca uses $guarded = [] vacío.

Eager Loading con with()

Si usarás relaciones en un @foreach, cárgalas antes con with().

Una migración = un cambio

Si olvidaste una columna, crea una nueva migración. Nunca edites las ya ejecutadas.

Fat Model, Thin Controller

La lógica compleja va en el Modelo, no en el Controlador.

Seeders idempotentes

Usa firstOrCreate() en seeders para no duplicar datos esenciales.
