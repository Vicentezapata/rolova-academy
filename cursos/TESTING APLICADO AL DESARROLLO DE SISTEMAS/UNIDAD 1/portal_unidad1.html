¿Que lograras en esta unidad?

Al completar la Unidad 1 habras desarrollado las siguientes competencias clave.

🔍
RA 1.1
Principios y objetivos del testing de software
Identifica errores de manera efectiva durante el proceso de testing
Aplica metodos de testing apropiados segun el contexto del proyecto
Utiliza herramientas de analisis para proponer mejoras al software
🏗️
RA 1.2
Niveles de prueba: unitaria, integracion, sistema, aceptacion
Distingue pruebas unitarias, de integracion, sistema y aceptacion
Determina la idoneidad de cada nivel segun las necesidades del proyecto
Analiza resultados para proponer ajustes en las estrategias de testing
⬜⬛
RA 1.3
Tipos de pruebas: tecnica y naturaleza
Diferencia caja blanca (con codigo) y caja negra (sin codigo)
Clasifica pruebas funcionales y no funcionales con ejemplos reales
Selecciona el tipo de prueba adecuado al contexto del software
🏗️ Estructura

Piramide de Niveles de Prueba

Los niveles se aplican de forma progresiva: desde el componente mas pequeno hasta la validacion con el cliente.

Pruebas de Aceptacion (UAT / BAT)
El software satisface las necesidades del cliente · Usuario / Cliente
Pruebas de Sistema
El sistema completo funciona correctamente · Equipo QA
Pruebas de Integracion
Los modulos interactuan correctamente · Dev + QA
Pruebas Unitarias
Cada componente funciona individualmente · Desarrollador

Evaluacion Sumativa — Unidad 1

Situacion problematica evaluada mediante rubrica.

Evaluacion U1 — Analisis de Caso de Software
Semana 5 · Plataforma EVA · Instrumento: Rubrica
10%
📋 Que debes hacer
Recibiras un caso de estudio de un sistema de software real. Deberas: (1) Identificar que tipos y niveles de prueba aplicarias; (2) Justificar la seleccion tecnicamente; (3) Describir al menos 3 casos de prueba con entradas, proceso y salida esperada; (4) Analizar que errores detectaria cada prueba.
CriterioLogrado (100%)Med. Logrado (60%)No Logrado (0%)
Identificacion de niveles Identifica todos los niveles pertinentes con justificacion solida Identifica la mayoria con justificacion parcial No identifica correctamente los niveles
Seleccion de tipos de prueba Selecciona el tipo mas adecuado con argumento tecnico solido Selecciona con justificacion basica Seleccion incorrecta sin justificacion
Diseno de casos de prueba Casos claros con entradas, proceso y resultado esperado Casos incompletos o poco claros No disena casos de prueba validos
Analisis y mejoras Propone mejoras y analiza posibles fallas con profundidad Analisis superficial No realiza analisis
Presentacion y claridad Redaccion clara, organizada, terminologia tecnica correcta Aceptable con algunos errores tecnicos Confusa o con errores graves
