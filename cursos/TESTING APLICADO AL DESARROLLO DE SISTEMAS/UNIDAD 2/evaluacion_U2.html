Criterio Esperado
Matriz RTM (35 pts): Se espera que el excel tenga columnas como "ID Requisito", "Descripción", "ID Caso Prueba".

Si dejan un requisito sin un caso de prueba asociado, significa que hay un "hueco de cobertura" y se descuentan puntos.
PARTE 1 (35 pts)

Matriz de Pruebas (RTM)

El equipo de desarrollo necesita saber exactamente qué pruebas cubren qué requisitos para asegurar que nada se quede fuera.

Instrucciones de Construcción:
  • Extracción: Identifica y enlista cada uno de los requerimientos y/o Historias de Usuario de los documentos provistos.
  • Vinculación: Crea identificadores únicos (ej. REQ-01, CP-01) y asocia cada requisito con su(s) respectivo(s) caso(s) de prueba.
  • Auditoría: Asegúrate visualmente (mediante la matriz) de que existe un 100% de cobertura teórica.
Criterio Esperado
Casos de Prueba (35 pts): Deberán usar la plantilla vista en clases.

Evalúa que no solo hagan escenarios de "Happy Path" (positivos). Para tener los 35 puntos deben incluir escenarios negativos (ej. qué pasa si falta un dato o ingresan un tipo erróneo).
PARTE 2 (35 pts)

Diseño del Plan y Casos

Basándote en la matriz RTM, es momento de diseñar los casos de prueba tácticos en la misma Hoja de Cálculo.

Instrucciones de Construcción:
  • Estructura Formal: Cada caso debe tener: ID, Precondiciones, Pasos, Datos y Resultado Esperado.
  • Exhaustividad: No pruebes solo cuando todo sale bien. ¿Qué pasa si el sistema falla? Diseña escenarios negativos.
  • Claridad Táctica: Los pasos deben ser lo suficientemente claros para que cualquier otra persona del equipo los ejecute.
Criterio Esperado
Gherkin (30 pts): Este es un documento PDF aparte.

La sintaxis debe ser estrictamente DADO/CUANDO/ENTONCES. Se castiga el uso de lenguaje técnico (ej. "DADO que el objeto JSON tiene id=1"). Debe ser lenguaje de Negocio.
PARTE 3 (30 pts)

Criterios de Aceptación (Gherkin)

El cliente quiere estar seguro de que entendimos el comportamiento esperado del sistema (BDD) antes de programarlo.

Instrucciones de Construcción:
  • Traducción a BDD: Genera todos los escenarios lógicos posibles para aplicar BDD en este software.
  • Sintaxis Estricta: Utiliza el estándar DADO (estado inicial), CUANDO (acción) y ENTONCES (resultado medible).
  • Formato: Entregar en el archivo PDF (Max 10 páginas, Arial 12, justificado).
