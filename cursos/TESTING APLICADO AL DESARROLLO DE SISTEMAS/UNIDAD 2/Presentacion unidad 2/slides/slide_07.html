Sesión 02 · Requerimientos SRS vs Historia de Usuario — Waterfall vs Agile S2
Requerimiento Tradicional (SRS)

Software Requirements Specification

Típico del modelo Cascada (Waterfall). Documentos extensos, formales, orientados al "Qué" debe hacer el sistema desde una perspectiva de ingeniería. Escrito por analistas, para ingenieros.

"El sistema deberá permitir la autenticación de usuarios contra el LDAP corporativo con encriptación SHA-256 dentro de un tiempo de respuesta < 200ms. El módulo deberá registrar cada intento en auditoría con timestamp UTC."
Documentación exhaustiva para contratos legales y proyectos regulados.
Preciso para equipos grandes y distribuidos con poca comunicación directa.
Historia de Usuario (Agile)

User Story: COMO / QUIERO / PARA

Un recordatorio para tener una conversación. Enfocado en el Valor de Negocio y en el Usuario. Usa lenguaje natural, escrito por (y para) el equipo de producto.

"COMO empleado remoto, QUIERO ingresar al sistema usando mi clave corporativa, PARA no tener que recordar contraseñas distintas."
Fomenta la colaboración y la comprensión compartida del objetivo.
Adaptable: se refina durante los sprints con nuevas conversaciones.
